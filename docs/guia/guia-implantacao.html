MK-EMPRESA · hEX RB750Gr3 · RouterOS 7

Rede unificada com failover Operadora A → Operadora B

Guia de campo passo a passo. O MikroTik é todo preparado em casa, hoje. Na empresa ele entra entre as operadoras e o switch de 24 portas, e os roteadores dos contêineres viram pontos de acesso de uma rede só. Cada passo traz onde clicar, o comando pronto para copiar e o que você deve ver para saber que deu certo.

Fase A · em casa, hoje
~40 min

Atualizar, gravar o script e testar o hEX na sua internet. Ele chega pronto.

Fase B · na empresa
~15 min + 10 por sala

MikroTik no rack e todas as salas com internet. Depois cada roteador de contêiner vira AP.

Plano B
volta em 5 min

Tire uma foto do rack antes. Para voltar, os cabos das operadoras voltam para as mesmas portas do switch.

Passos e progresso
Vocabulário rápido do MikroTik (1 minuto)
Winbox
Programa do Windows para configurar o MikroTik com janelas e menus. Conecta até pelo MAC, sem IP.
RouterOS
O sistema do MikroTik. Precisamos da versão 7.
New Terminal
Linha de comando dentro do Winbox. Tudo que tem bloco "RouterOS" aqui é colado nele.
Bridge
Junta portas numa rede só. A bridge-LAN une ether3, ether4 e ether5 como um switch.
DHCP Client
O MikroTik pedindo IP ao roteador da operadora, como um PC faria.
Distance
Prioridade da rota. Menor ganha: Operadora A = 1, Operadora B = 2.
Rota recursiva
A rota da Operadora A só fica ativa se um IP da internet responder por ela. É o que detecta "modem ligado, internet caída".
Netwatch
Monitor que pinga a cada 15 s e tira a Operadora A do ar se a perda ou a latência ficarem ruins.
Masquerade (NAT)
Faz a rede interna sair para a internet com o IP da WAN.
Safe Mode
Botão no topo do Winbox. Se você perder o acesso por um erro, o MikroTik desfaz sozinho.

O que levar amanhã

  • O hEX já preparado (Fase A) e a fonte dele

Fase A

em casa, hoje · ~40 min

Tudo aqui é feito na sua mesa, com a sua internet. Se algo der errado, você tem tempo para resolver sem ninguém esperando.

A1

Baixar o Winbox

Baixe no site oficial: mikrotik.com/download, seção WinBox, versão Windows 64-bit. É um executável só, não precisa instalar.

Na primeira vez que abrir, o Windows vai perguntar sobre o firewall. Clique em Permitir acesso. Sem isso, a aba Neighbors não encontra o MikroTik.

A2

Salvar o script no notebook

Este é o arquivo que configura o MikroTik inteiro: portas, rede 172.16.10.x, DHCP, os dois links, failover, NAT, firewall e segurança. Clique em Copiar e depois rode o comando do PowerShell logo abaixo. Ele grava o conteúdo copiado como failover.rsc na sua Área de Trabalho, sem os caracteres invisíveis que o Bloco de Notas às vezes coloca e que quebram o script.

failover.rsc · script completo
# =====================================================================
#  MikroTik hEX (RB750Gr3) - Failover OPERADORA A (primario) / OPERADORA B
#  RouterOS 7.x (>= 7.4, recomendado ultima stable)
#
#  Portas:
#    ether1 = OPERADORA A      (LAN do roteador da Operadora A -> DHCP)
#    ether2 = OPERADORA B  (LAN do roteador da Operadora B -> DHCP)
#    ether3..ether5 = LAN (APs / switch)
#
#  LAN: 172.16.10.0/24  (gateway 172.16.10.1)
#
#  Uso (recomendado): subir este arquivo em Files e resetar com:
#    /system reset-configuration no-defaults=yes skip-backup=yes run-after-reset=failover.rsc
#  O script roda sozinho no boot. Confira no Log: "failover.rsc aplicado com sucesso"
# =====================================================================

# Aguarda as interfaces subirem (necessario no run-after-reset)
:delay 15s

# ---------- Identidade / relogio ----------
/system identity set name=MK-EMPRESA
/system clock set time-zone-name=America/Sao_Paulo

# ---------- Interfaces ----------
/interface ethernet
set [find default-name=ether1] name=ether1-OPA
set [find default-name=ether2] name=ether2-OPB

/interface bridge
add name=bridge-LAN comment="LAN unificada"

/interface bridge port
add bridge=bridge-LAN interface=ether3
add bridge=bridge-LAN interface=ether4
add bridge=bridge-LAN interface=ether5

/interface list
add name=WAN
add name=LAN

/interface list member
add list=WAN interface=ether1-OPA
add list=WAN interface=ether2-OPB
add list=LAN interface=bridge-LAN

# ---------- LAN / DHCP / DNS ----------
/ip address
add address=172.16.10.1/24 interface=bridge-LAN comment=LAN

/ip pool
add name=pool-LAN ranges=172.16.10.100-172.16.10.250

/ip dhcp-server
add name=dhcp-LAN interface=bridge-LAN address-pool=pool-LAN lease-time=8h

/ip dhcp-server network
add address=172.16.10.0/24 gateway=172.16.10.1 dns-server=172.16.10.1

# DNS do MikroTik. NAO usar aqui os IPs de monitoramento (208.67.222.222 / 9.9.9.9)
/ip dns
set servers=1.1.1.1,8.8.8.8 allow-remote-requests=yes cache-size=4096KiB

# ---------- Rotas recursivas (failover por disponibilidade) ----------
# Host de checagem da OPERADORA A: 208.67.222.222 (OpenDNS) - sempre sai pela Operadora A
# Host de checagem da OPERADORA B: 9.9.9.9 (Quad9)        - sempre sai pela Operadora B
# Gateways abaixo sao placeholders; o script do DHCP corrige sozinho.
/ip route
add dst-address=208.67.222.222/32 gateway=192.168.10.1 scope=10 comment=OPA-CHECK
add dst-address=9.9.9.9/32 gateway=192.168.20.1 scope=10 comment=OPB-CHECK
add dst-address=0.0.0.0/0 gateway=208.67.222.222 target-scope=11 check-gateway=ping distance=1 comment=OPA-DEFAULT
add dst-address=0.0.0.0/0 gateway=9.9.9.9 target-scope=11 check-gateway=ping distance=2 comment=OPB-DEFAULT

# ---------- WANs (DHCP client sem rota default) ----------
# O script atualiza o gateway da rota de checagem sempre que o DHCP renova,
# entao nao importa qual IP o roteador da operadora usa.
/ip dhcp-client
add interface=ether1-OPA add-default-route=no use-peer-dns=no use-peer-ntp=no comment=OPA \
    script=":if (\$bound=1) do={ /ip route set [find where comment=\"OPA-CHECK\"] gateway=\$\"gateway-address\" }"
add interface=ether2-OPB add-default-route=no use-peer-dns=no use-peer-ntp=no comment=OPB \
    script=":if (\$bound=1) do={ /ip route set [find where comment=\"OPB-CHECK\"] gateway=\$\"gateway-address\" }"

# ---------- NAT ----------
/ip firewall nat
add chain=srcnat out-interface=ether1-OPA action=masquerade comment="NAT OPA"
add chain=srcnat out-interface=ether2-OPB action=masquerade comment="NAT OPB"

# ---------- Firewall basico ----------
/ip firewall filter
add chain=input action=accept connection-state=established,related,untracked comment="IN: estabelecidas"
add chain=input action=drop connection-state=invalid comment="IN: invalidas"
add chain=input action=accept protocol=icmp comment="IN: ping"
add chain=input action=accept in-interface-list=LAN comment="IN: gerencia/DNS/DHCP so pela LAN"
add chain=input action=drop comment="IN: dropa o resto (WAN)"
add chain=forward action=fasttrack-connection connection-state=established,related comment="FW: fasttrack"
add chain=forward action=accept connection-state=established,related,untracked comment="FW: estabelecidas"
add chain=forward action=drop connection-state=invalid comment="FW: invalidas"
add chain=forward action=drop connection-state=new connection-nat-state=!dstnat in-interface-list=WAN comment="FW: bloqueia novas vindas da WAN"

# ---------- Hardening ----------
/ip service
set telnet disabled=yes
set ftp disabled=yes
set www disabled=yes
set api disabled=yes
set api-ssl disabled=yes
set winbox address=172.16.10.0/24
set ssh address=172.16.10.0/24

/tool mac-server set allowed-interface-list=LAN
/tool mac-server mac-winbox set allowed-interface-list=LAN
/ip neighbor discovery-settings set discover-interface-list=LAN

# ---------- NTP ----------
/system ntp client set enabled=yes
/system ntp client servers
add address=a.st1.ntp.br
add address=b.st1.ntp.br

# ---------- Netwatch (degradacao: perda/latencia) ----------
# Se a Operadora A ficar com >30% de perda ou media >300ms, desativa a rota dela.
# Em qualquer troca, limpa as conexoes para os apps reconectarem pelo link novo.
# Fica por ultimo e protegido: se der erro de sintaxe, o resto ja foi aplicado.
:do {
/tool netwatch add name=OPA-MON type=icmp host=208.67.222.222 interval=15s packet-count=10 packet-interval=200ms thr-avg=300ms thr-max=2s thr-jitter=1s thr-stdev=500ms thr-loss-percent=30% down-script="/ip route disable [find where comment=\"OPA-DEFAULT\"]; :delay 1s; /ip firewall connection remove [find]; :log warning \"OPERADORA A FORA/DEGRADADA -> usando OPERADORA B\"" up-script="/ip route enable [find where comment=\"OPA-DEFAULT\"]; :delay 1s; /ip firewall connection remove [find]; :log warning \"OPERADORA A OK -> voltando para OPERADORA A\""
:log info "NETWATCH OK"
} on-error={ :log error "NETWATCH FALHOU - criar manualmente (ver guia)" }

:log info "failover.rsc aplicado com sucesso"
PowerShell · grava o que foi copiado
[IO.File]::WriteAllText("$env:USERPROFILE\Desktop\failover.rsc", (Get-Clipboard -Raw))

  3. Volte ao PowerShell e aperte Enter.

Fase B

na empresa · ~15 min + ~10 min por sala

A internet de todos cai só uma vez, por uns 2 minutos, no passo B2. Depois do B3 todas as salas já navegam com failover. A conversão dos roteadores das salas (B4) é feita uma sala por vez e, se o tempo apertar, pode ficar para outro dia.

B1

Levantamento rápido

~10 minnada muda ainda

1. Foto do rack. Antes de tocar em qualquer cabo, fotografe o switch de 24 portas e etiquete os cabos que vêm dos roteadores Operadora A e Operadora B. É o seu caminho de volta.

2. Faixa de IP de cada operadora. Ligue o notebook direto no roteador da Operadora A (cabo ou Wi-Fi) e rode o comando abaixo. Depois repita no da Operadora B.

CMD · rode uma vez em cada operadora
ipconfig | findstr /i "IPv4 Gateway"
Se as duas faixas forem iguais

Por exemplo, as duas em 192.168.1.x: entre na página do roteador da Operadora B e mude a LAN dele para 192.168.50.1. Com faixas iguais, o MikroTik não sabe para qual lado mandar.

3. Como cada sala está hoje. Num PC de cada contêiner, rode:

CMD · num PC dentro da sala
ipconfig | findstr /i "IPv4 Gateway"
tracert -d -h 3 8.8.8.8

O primeiro salto do tracert é o roteador da sala e o segundo é o da operadora. Assim você sabe por qual link a sala sai hoje e confirma que o roteador da sala está em modo roteador (é o que muda no B4). Anote a marca e o modelo do roteador de cada sala e se você tem a senha de admin dele.

4. Aparelhos com IP fixo. Impressoras, relógio de ponto, DVR ou servidor costumam ter IP fixo e vão sumir depois da troca. Descubra quem está em cada rede (troque 192.168.15 pela faixa encontrada):

CMD · varredura rápida (~30 s) + lista de MACs
for /L %i in (1,1,254) do @ping -n 1 -w 100 192.168.10.%i | find "TTL"
arp -a

Anote nome, IP antigo e MAC de cada aparelho fixo. Vão virar reservas no passo B5. Se preferir, o Advanced IP Scanner faz o mesmo e já mostra nomes e fabricantes.

B2

Colocar o MikroTik no rack

~5 mininternet cai para todos por ~2 min
  1. Desligue o Wi-Fi dos roteadores Operadora A e Operadora B, pela página de cada um. Não mexa em mais nada neles.
  2. Tire do switch o cabo que vem do roteador Operadora A e ligue na ether1 do hEX.
  3. Tire do switch o cabo que vem do roteador Operadora B e ligue na ether2.
  4. Ligue um cabo curto da ether3 do hEX a uma porta livre do switch (pode ser a que a Operadora A usava).
  5. Ligue o hEX. Em 1 a 2 minutos as salas voltam a ter internet.

Regra de ouro

O switch de 24 portas passa a receber internet por um único cabo: o da ether3. Nenhum roteador de operadora pode continuar ligado no switch, senão volta a ter dois DHCPs na rede e a bagunça de hoje.

B4

Converter o roteador de cada contêiner em AP

~10 min por salauma sala por vezsó aquela sala fica sem rede

Hoje o roteador de cada sala recebe a internet pela porta WAN e cria uma rede própria lá dentro, com NAT. Por isso as salas não se enxergam. Em modo AP ele deixa de ser roteador: vira só a antena Wi-Fi e as portas de rede da sala, dentro da rede 172.16.10.x.

Ordem que não te deixa sem acesso

  1. Ligue o notebook por cabo numa porta LAN do roteador da sala e abra a página dele (o gateway que o ipconfig mostrar; costuma ser 192.168.20.1, 192.168.1.1 ou tplinkwifi.net).
  2. Se existir Modo de operação › Access Point (comum em TP-Link, Intelbras e Mercusys), use: ele já desliga o DHCP e o NAT. Defina o IP de LAN e pule para o item 4.
  3. Sem esse modo, faça à mão:
    • LAN: IP 172.16.10.1N, máscara 255.255.255.0. Se pedir gateway e DNS, use 172.16.10.1.
    • DHCP: desativar o servidor.
  4. Wi-Fi: o SSID e a senha únicos, WPA2-PSK (AES). No 2.4 GHz, alterne os canais 1, 6 e 11 entre salas vizinhas. Salve. A página vai parar de responder, e isso é normal.
  5. Passe o cabo que vem do switch da porta WAN para uma porta LAN. A porta WAN fica vazia.
  6. Renove o IP do notebook e confira:
CMD · troque 11 pelo IP da sala
ipconfig /release
ipconfig /renew
ipconfig /all | findstr /i "IPv4 Gateway DHCP"
ping 172.16.10.11
curl.exe -s https://ifconfig.me/ip
Você deve ver

IP 172.16.10.1xx, gateway 172.16.10.1 e Servidor DHCP 172.16.10.1. O roteador da sala responde no IP novo e a internet funciona.

Servidor DHCP diferente de 172.16.10.1?

Algum roteador ficou com o DHCP ligado e está distribuindo IP errado, que é exatamente o problema de hoje. O IP mostrado no ipconfig indica qual é. Entre nele e desligue o DHCP.

Para o MikroTik avisar sozinho se aparecer um DHCP intruso em qualquer sala:

RouterOS · Terminal · alerta de DHCP intruso no Log
/ip dhcp-server alert add interface=bridge-LAN alert-timeout=1h on-alert=":log warning \"DHCP INTRUSO na rede - verificar roteadores das salas\""
Sem a senha do roteador da sala?

Com ele ligado, segure o botão reset por uns 10 s. Ele volta à configuração de fábrica, com a senha da etiqueta. Depois configure do zero seguindo os itens acima.

Contêiner é metálico

O sinal fica bem preso dentro de cada sala, então a interferência entre salas é pequena. Com o mesmo nome de Wi-Fi em todas, quem anda de uma sala para outra reconecta sozinho em poucos segundos. Não é mesh, mas acaba a confusão de "qual rede eu uso".

B6

Liberar a comunicação entre os PCs

A rede nova é tratada pelo Windows como "Pública" na primeira conexão, e isso bloqueia pastas compartilhadas e a descoberta de outros PCs. Rode em cada PC que precisa compartilhar ou acessar algo. Os comandos funcionam em Windows em português ou inglês.

PowerShell (Administrador) · rede privada + descoberta + compartilhamento
Get-NetConnectionProfile | Set-NetConnectionProfile -NetworkCategory Private
Enable-NetFirewallRule -Group "@FirewallAPI.dll,-32752"
Enable-NetFirewallRule -Group "@FirewallAPI.dll,-28502"
Get-NetConnectionProfile | Select-Object InterfaceAlias, NetworkCategory
Você deve ver

A última linha mostra Private. As duas do meio ligam "Descoberta de Rede" e "Compartilhamento de Arquivo e Impressora".

Teste de um PC para o outro:

Um PC não responde ao ping?

O firewall dele ainda está em modo Público, ou ele pegou IP antes do Wi-Fi mudar. Rode ipconfig /renew e depois os comandos acima.

Problemas comuns

Netwatch falhou (no Log aparece "NETWATCH FALHOU")

Sua versão do RouterOS usa outros nomes de parâmetro. O failover principal (rota recursiva) funciona do mesmo jeito. Crie um Netwatch simples, que funciona em qualquer versão 7:

RouterOS · Terminal · Netwatch simples
/tool netwatch add name=OPA-MON host=208.67.222.222 interval=10s timeout=1s down-script="/ip route disable [find where comment=\"OPA-DEFAULT\"]; /ip firewall connection remove [find]; :log warning \"OPERADORA A FORA -> usando OPERADORA B\"" up-script="/ip route enable [find where comment=\"OPA-DEFAULT\"]; /ip firewall connection remove [find]; :log warning \"OPERADORA A OK -> voltando para OPERADORA A\""

DHCP Client em "searching..."

  • O cabo está na porta WAN do roteador da operadora? Tem que ser em uma porta LAN.
  • O DHCP do roteador da operadora está ligado? Precisa estar.
  • Troque o cabo e veja se o LED da porta do hEX acende.

Sala sem internet depois da troca

O roteador dessa sala provavelmente tem a WAN com IP fixo na faixa antiga. Entre na página dele e mude a WAN para IP dinâmico / DHCP, ou já faça a conversão para AP do B4. Com o notebook na LAN desse roteador, tracert -d -h 3 8.8.8.8 deve mostrar 172.16.10.1 no segundo salto.

O MikroTik tem internet, mas os PCs não

CMD · diagnóstico no PC
ipconfig /all | findstr /i "IPv4 Gateway DNS"
ping 172.16.10.1
nslookup google.com 172.16.10.1
tracert -d -h 4 8.8.8.8

O PC precisa ter IP 172.16.10.x, gateway e DNS 172.16.10.1. Se tiver IP 169.254.x.x, não pegou DHCP: confira o cabo ou o AP (DHCP do AP tem que estar desligado).

Winbox não encontra o hEX

PowerShell (Administrador) · liberar o Winbox no firewall · ajuste o caminho do .exe
New-NetFirewallRule -DisplayName "Winbox" -Direction Inbound -Action Allow -Program "$env:USERPROFILE\Downloads\winbox64.exe"

Se ainda assim não aparecer, dê IP fixo ao notebook e conecte pelo IP:

CMD (Administrador) · IP fixo e depois volta para DHCP · troque "Ethernet" pelo nome da sua placa
netsh interface ip set address name="Ethernet" static 172.16.10.9 255.255.255.0 172.16.10.1
netsh interface ip set address name="Ethernet" dhcp

Travei o acesso ao MikroTik

Com o hEX ligado, segure o botão RESET até o LED de status começar a piscar (uns 5 s) e solte. Ele volta à configuração de fábrica (192.168.88.1). O arquivo failover.rsc continua em Files: repita o passo A7.

Algum site ou sistema reclama depois da troca de link

Normal por alguns segundos: o script derruba as conexões antigas para elas se refazerem pelo link novo. Se um sistema específico exigir IP fixo da Operadora A (liberação por IP no banco ou em ERP), ele só vai funcionar pela Operadora A. Anote e me avise, porque dá para forçar esse destino sempre pela Operadora A.
